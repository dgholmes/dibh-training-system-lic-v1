## 부수적으로 확인된 사항

- R01·R02의 잔여 시도 횟수 문구는 **실행 시점에 동적으로 조합**되는 메시지로, 소스 문자열
  추출만으로는 목록화되지 않습니다. 실제 조건 재현을 통해서만 확인되는 항목입니다.
- R03 → R04 순서는 계정 잠금이 **정상 비밀번호에 대해서도 유지**됨을 보여줍니다(IA-02).
- R07~R11은 `validatePassword()`가 위반된 규칙만 선별하여 반환함을 보여줍니다. 각 캡처는
  해당 규칙 **한 가지만** 위반하는 값을 입력하여 취득하였으며, 다섯 규칙(길이·대문자·소문자·
  숫자·특수문자)이 각각 독립적으로 강제됨을 확인합니다(IA-05).
- R13은 파일 선택기가 `accept` 속성으로 1차 필터링을 수행함에도 불구하고, **앱이 파일명
  확장자를 별도로 재검증**하여 지원하지 않는 형식을 거부함을 보여줍니다.
- R14·R15는 백업 파일 손상의 **두 가지 계층**을 구분하여 보여줍니다.
  - R14: 암호문 자체가 손상된 경우 → AES-256-GCM 인증 태그 검증 실패로 복호화 단계에서 차단.
    앱이 생성한 실제 백업 파일의 암호문 중 8자리 hex를 변조하여 재현하였습니다.
  - R15: 복호화는 통과하였으나 봉투 내부 본문이 기록된 SHA-256 해시와 불일치하는 경우 →
    무결성 검증 단계에서 차단. 설치 키는 Android Keystore로 봉인되어 외부에서 재암호화가
    불가능하므로, 평문 봉투(`{hash, data}`) 형식의 백업 파일에서 본문만 변조하여 재현하였습니다.
- 모든 캡처는 릴리즈 빌드에서 취득되었으므로 DEBUG 배너가 없으며, 하단에 버전(v1.1.6)과
  유통표준코드(GTIN-13)가 함께 표시됩니다.
- 재현 시 사용한 관리자 비밀번호: 초기값 `Admin@1234!` → 변경값 `NewPass1!@`.

## 실제 조건 재현이 불가능한 항목

| 조건 | 대상 메시지 | 재현 불가 사유 |
|---|---|---|
| 마지막 계정 삭제 시도 | 마지막 계정은 삭제할 수 없습니다. | 계정 관리 화면은 **로그인 중인 본인 계정에는 [삭제] 버튼을 렌더링하지 않으므로**(`u.id !== session?.userId`), 계정이 1개만 남은 상태에서는 삭제를 호출할 수단이 없습니다. `UserStore.delete()`의 `users.length <= 1` 검사는 심층 방어(defence-in-depth) 가드이며, UI 경로로는 도달하지 않습니다. |
| 시작 자가진단 실패 | Web Crypto / sessionStorage / localStorage 사용 불가 | 앱 로드 이전에 브라우저 API를 비활성화해야 하므로 실기 재현이 불가능합니다. `../SI-07-error-messages/` 의 UI 렌더링 캡처로 대체합니다. |
