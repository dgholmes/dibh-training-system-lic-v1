## 캡처 방법

`scripts/capture-real-conditions.mjs` 가 Chrome DevTools Protocol로 앱을 조작합니다.
각 항목은 **조작자가 실제로 하는 동작**을 그대로 수행하여 메시지를 발생시킵니다 —
문자열을 화면에 그려 넣는 방식이 아닙니다.

```bash
npm run dev                                  # 또는 preview 서버
node scripts/capture-real-conditions.mjs
```

- 전제 조건이 클릭만으로 도달하기 어려운 경우(계정 잠금 상태, 비밀번호 경과일)에는
  **상태만 미리 심고**, 메시지 자체는 앱의 원래 코드 경로가 생성합니다.
- 각 캡처는 **기대 문구가 실제로 화면에 있는지 확인한 뒤에만** `verified`로 기록됩니다.
  문구가 없으면 `MISS`로 남습니다 — 나타나지 않은 메시지의 스크린샷은 증적이 아니라
  오해의 소지이기 때문입니다.

## 아직 캡처하지 못한 항목과 그 이유

정직하게 기록합니다. 아래는 **캡처 실패가 아니라, 현재 조건에서 발생시킬 수 없거나
추가 작업이 필요한 항목**입니다.

### (가) 브라우저에서 원리적으로 발생하지 않는 것

| # | 메시지 | 사유 |
|---|---|---|
| 1, 2 | 암호화 키 오류 / 저장된 암호화 키를 복구할 수 없습니다 | 봉인 키(`dibh_install_key_v2`)는 **Android Keystore 경로에서만** 사용됩니다. 브라우저 빌드는 기존 localStorage 방식을 쓰므로 이 차단 화면에 도달할 수 없습니다. **실기기에서 취득해야 합니다.** |
| 3, 4, 11, 12, 13 | 무결성 검사 실패 계열 | `main.jsx:144` 의 `import.meta.env.PROD` 안에 있어 **개발 서버에서는 실행되지 않습니다.** `npm run build` 후 `dist/integrity.json` 을 변조한 preview 서버에서 취득해야 합니다. |

### (나) UI 경로가 존재하지 않는 것

| # | 메시지 | 사유 |
|---|---|---|
| 35 | 마지막 계정은 삭제할 수 없습니다 | 삭제 버튼은 `u.id !== session?.userId` 일 때만 렌더링됩니다. 계정이 하나뿐이면 그 계정이 곧 로그인 계정이므로 **삭제 버튼 자체가 표시되지 않습니다.** 저장소 계층의 방어 코드이며 화면에서 도달할 수 없습니다. 문구 유지는 타당하나, **증적으로 캡처할 수 없다는 점을 기록**합니다. |

### (다) 추가 작업이 필요한 것

| # | 메시지 | 현재 상태 |
|---|---|---|
| 20, 23 | 비밀번호 변경 주기 도래 / 변경 예정 안내 | `passwordChangedAt` 을 앞당겨 심는 방식으로 시도했으나 재현되지 않았습니다. 기존 증적 `IA-04-password-cycle/` 은 **실기기 시계**로 취득한 것이며, 그 방식이 더 확실합니다. |
| 24 | 비밀번호가 일치하지 않습니다 | 강제 변경 모달에서 서로 다른 값 제출 시 표시되어야 하나 재현되지 않았습니다. 폼 제출 경로 확인 필요. |
| 46, 47, 48 | 백업 복구 실패 계열 | 복구 화면의 파일 입력 요소를 자동화에서 찾지 못했습니다(`no file input on backup screen`). 화면 구조 확인 후 재시도 필요. |
| 그 외 | 위 표에 없는 나머지 문구 | 자동화 케이스를 아직 작성하지 않았습니다. 발생 조건은 목록 문서에 기재되어 있으므로 케이스 추가로 확장 가능합니다. |
